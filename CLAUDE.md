# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Development (HMR via electron-vite)
npm run dev

# Production build (outputs to out/)
npm run build

# Package into installer (dist/)
npm run dist

# Recompile native modules (node-pty, better-sqlite3) after electron version changes
npm run rebuild

# Type-check both projects (web + node) — the correctness gate
npm run typecheck
```

**Risky pure logic is extracted into dependency-free modules specifically so it can be unit-tested** — renderer logic under `src/lib/` (e.g. `lineDiff.ts` — the Composer's LCS diff; `mention.ts` — the @-mention caret parser; `snippets.ts` — snippet CRUD/parse) and main-process logic under `electron/lib/` (e.g. `aiParse.ts` — `stripCodeFences`/`extractJsonObject`, the shared defensive parsing every LLM-response handler uses). These import nothing from React/CodeMirror/Electron, so they strip-and-run straight from source with no build step. `npm test` (`node --experimental-strip-types tests/lib-units.mts`, Node 22+) runs the committed assertions for all of the above — **add a block to `tests/lib-units.mts` whenever you add a new pure module under `src/lib/` or `electron/lib/`**, and keep it green. (The other `tests/*.mjs` — `smoke`, `editor-verify` — are Playwright integration checks that boot the built app; this is the no-build unit layer.) Prefer this pattern for new algorithmic code: keep it pure, in a `lib/`, and assert against it. TypeScript type-checking remains the primary correctness gate, and `npm run typecheck` (runs `tsc --noEmit` over `tsconfig.web.json` and `tsconfig.node.json`) is currently **clean** — keep it that way. The build (`electron-vite`/esbuild) does **not** gate on type errors, so run `npm run typecheck` before declaring work done. Note: `tsc` is `composite`, so a stale `*.tsbuildinfo` can mask the effect of new `.d.ts` files — delete `tsconfig.web.tsbuildinfo` if an augmentation isn't taking.

## Architecture

SwarmMind is an Electron desktop app that runs multiple AI coding CLIs side-by-side in resizable terminal panes, with a shared MCP memory server so agents can exchange context.

### Process boundary

The renderer (React) and main process (Node.js) are strictly isolated via contextBridge:
- `electron/preload.ts` — exposes the entire IPC surface as `window.swarmmind`
- `src/types/swarmmind.d.ts` — TypeScript types for `window.swarmmind`

**Never call Node.js APIs directly from React code.** Every cross-process call must go through `window.swarmmind.*`.

### Dual SQLite databases

Two independent `better-sqlite3` connections live in `memory/db.ts`:

| Connection | Path | Tables |
|---|---|---|
| `appDb` | `userData/app.db` | `workspaces`, `skills`, `app_state` |
| `workspaceDb` | `{rootPath}/.swarmmind/memory.db` | `memory_entries`, `tasks`, `pane_layouts`, `agent_configs`, `messages` |

`initAppDb()` runs once at startup. `initWorkspaceDb()` runs each time the user opens a workspace (the previous connection is closed first). All query helpers in `memory/queries.ts` call `getAppDb()` or `getWorkspaceDb()` — never the wrong one.

### MCP server

`mcp/server.ts` runs an Express/SSE HTTP server inside the main process (preferred port 57400, falls back to OS-assigned). Tools and resources are registered in `mcp/tools.ts` and `mcp/resources.ts`. The active workspace ID is tracked via `setActiveWorkspace()` so tools always query the correct DB.

**Auth:** the SSE endpoint is gated on a bearer token derived per workspace (`getMcpToken(workspaceId)` = HMAC of a per-run master secret over the workspace id). It's appended to the injected SSE URL (`?token=…&ws=…`) and exposed as `SWARMMIND_MCP_TOKEN`, so only agents SwarmMind spawns can reach the server even though it binds `127.0.0.1`. `/mcp/sse` requires the token to match the one derived for the requested `ws` (constant-time compare), so a token issued for one workspace can't be replayed against another by swapping `?ws=` — each token authorizes only its own workspace's DB.

**Tools:** `memory_read/write/delete/list`; `task_create/update/list/get/note`; `send_message`. `task_note` appends a timestamped progress note (status unchanged); `task_get` returns full detail; `send_message(to,from,message)` queues a directed agent→agent message in the `messages` table, which the renderer-side conductor delivers by injecting into a free running pane of the recipient agent (see `useConductor.ts::deliverMessages`, runs every tick regardless of orchestration mode).

At agent spawn time, `electron/pty-manager.ts::injectMcpConfig()` writes the MCP SSE URL (with token) into each agent's config file (e.g., `{cwd}/.claude/settings.json` for Claude Code).

**Secrets:** agent API keys are encrypted at rest via Electron `safeStorage` (`electron/secrets.ts`), wrapped by `electron/agent-config.ts::readAgentConfig/writeAgentConfig` (settings IPC reads/writes go through these). Legacy plaintext keys are read unchanged and re-encrypted on next write; if the OS keychain is unavailable, it falls back to plaintext rather than failing the save.

### AI provider abstraction

Every in-app AI surface (SwarmAgent chat + widget, Cmd-K inline edit, ghost text, Composer, diagnostics, next-edit) goes through **one** entry point — `runChat()` in `electron/ai/client.ts` — so the vendor is a setting, not a hard-coded dependency. `electron/ipc/swarmagent.ts` only builds prompts and parses responses; it contains no vendor SDK calls.

- **Providers** (`electron/lib/aiProvider.ts`, pure + unit-tested): `groq`, `anthropic`, `openai`, `custom`. All except Anthropic are OpenAI-compatible and share one client (`groq-sdk` with a `baseURL` — it's a Stainless-generated OpenAI-compatible client, so no second HTTP dep). `custom` covers Ollama / LM Studio / OpenRouter / vLLM and needs no key.
- **Anthropic uses the official `@anthropic-ai/sdk`** (a runtime dependency). Its Messages API shape differs from OpenAI's, so the translation is pure and unit-tested in `aiProvider.ts`. Three things there are load-bearing and fail *silently* rather than loudly: `system` must be lifted out of the message array into a top-level parameter; **consecutive tool results must merge into one user message** (splitting them trains the model out of parallel tool calls with no error); and blank text blocks are rejected, so they're dropped. Claude also rejects `temperature`/`top_p` outright — the Anthropic path never sends them — and a safety decline arrives as a *successful* response with `stop_reason: 'refusal'`, which `refusalMessage()` turns into a real error instead of a blank reply.
- **Everything is streamed on the Anthropic path** (`messages.stream()` + `finalMessage()`), which sidesteps the SDK's HTTP timeout at large `max_tokens` and keeps one code path for streaming and non-streaming callers. `ChatRequest.fast` (ghost text, inline edit) disables Claude's thinking — it would otherwise consume the whole token budget on a one-line answer — and lowers temperature on OpenAI-compatible providers.
- **Keys and models are stored per provider** (`swarmAgentApiKey:<id>`, `swarmAgentModel:<id>`), so switching vendors doesn't discard the other's key; the pre-multi-provider `swarmAgentApiKey`/`swarmAgentModel` settings are still read as a Groq fallback so existing installs upgrade untouched. Provider/base URL live in `swarmAgentProvider`/`swarmAgentBaseUrl`; Settings → General renders the picker from `swarmAgent:providers`.

**Untrusted-workspace spawn safety:** `agent_configs` lives in the per-repo workspace DB (`{rootPath}/.swarmmind/memory.db`), so opening a cloned repo loads attacker-controllable config, and the spawn-affecting fields (`executablePath`/`extraFlags`/`env`) feed the launched shell command — a zero-click RCE if honored blindly. `writeAgentConfig` signs those three fields with a per-install HMAC key kept in `app.db` (userData, never in a repo), and the spawn path reads via `readAgentConfigForSpawn`, which **drops** them unless the signature verifies. So values configured through *this* install's Settings work; values shipped inside a repo are ignored (re-save in Settings to trust them). Defense-in-depth: `pty-manager.ts::buildShellCommand`/`quoteForShell` shell-quote every argv token (PowerShell single-quotes + call operator, bash single-quotes, cmd caret-escapes metachars) since `node-pty` must wrap the command in a shell on Windows.

### PTY spawning (Windows critical path)

`node-pty` cannot spawn `.cmd` scripts directly on Windows. `resolveSpawn()` in `electron/pty-manager.ts` wraps every agent command in the user's selected shell:

**Output is batched, not per-chunk.** `node-pty` emits at sub-millisecond granularity; forwarding every chunk individually cost an IPC hop *plus* (for agent panes) a fresh 4 KB tail allocation and a full cost re-scan — all on the main process, which also pumps every *other* pty, SQLite, the MCP server and the LSP client, so one noisy pane degraded every pane. `attachPty` now coalesces a pane's chunks into a frame-sized window (`OUTPUT_FLUSH_MS`, 12ms) and runs the tail/`parseCostUsd`/idle-timer work once per flush. Ordering is preserved (one FIFO buffer per pane); `onExit` flushes before emitting `pty:exit` so trailing output isn't dropped, and `ptyKill` flushes synchronously so a dying pty's last frame can't interleave with a replacement pty's output in the same pane. `npm run pty-verify` drives a real shell and asserts both halves: output arrives complete and in order, **and** stays coalesced (400 lines → single-digit IPC messages). If that ratio assertion ever fails, batching has been refactored away.

- `powershell` → `powershell.exe -NoLogo -NoExit -Command <cmd>`
- `cmd` → `cmd.exe /k <cmd>`
- `bash` → `bash.exe -i -c <cmd>` (Git Bash or WSL's bash, whichever is on PATH)

On non-Windows the command is wrapped in `$SHELL -c <cmd>` so quoted args/paths survive. The shell style (`ShellStyle = 'powershell' | 'cmd' | 'bash'`) is stored in Zustand (`shellStyle`) and persisted via `appsetting:set`. Users configure it in Settings → General.

### Session resume

Reopening a workspace automatically relaunches each pane's agent **and** restores its prior conversation — no user action. The mechanism:

- When an agent spawns, the pane leaf records `agentRunning: true` and a `sessionId` (a UUID minted on fresh spawn). Both are persisted in the layout JSON. `killAll()` kills **silently** (suppresses `pty:exit`) so quitting/workspace-switch doesn't clear those flags.
- On load, `sanitizeLoadedLayout()` in `workspace.ts` turns any `agentRunning` leaf into a queued auto-spawn (`pendingAutoSpawn: true`, `resume: true`) instead of wiping it, preserving `agentId`, `cwd`, and `sessionId`.
- `ptyCreate(..., resume, sessionId)` resolves the launch via `buildLaunchArgs()` in `pty-manager.ts`. Claude uses a caller-chosen session id for **per-pane** continuity: fresh = `claude --session-id <uuid>`, resume = `claude --resume <uuid>` (both non-interactive — no picker). Agents without a controllable session id fall back to `AGENT_RESUME_ARGS` ("continue last", e.g. `codex resume --last`, `opencode --continue`); the rest relaunch fresh.

**StrictMode gotcha (the auto-spawn effect in `AgentPane.tsx`):** the deferred-spawn timer must **not** be cancelled in the effect cleanup. React StrictMode runs effects mount→cleanup→mount in dev; a `clearTimeout` in cleanup kills the only scheduled spawn while the `autoSpawnedRef` guard blocks rescheduling, so the agent never launches (blank pane). Guard the timer callback with a mount ref instead. This only bites in `npm run dev`, not packaged builds.

### Multi-pane orchestration & extras

Features layered on top of the pane model:

- **Broadcast & selection** (`BroadcastBar.tsx`, store `selectedPaneIds`/`broadcastBarOpen`): Ctrl/⌘-click a pane title bar to select it; the broadcast bar (TopBar button or Ctrl/⌘-B) sends one prompt to selected panes, or all when none are selected, via `window.swarmmind.ptyInput`.
- **Pipe** (AgentPane context menu): route a pane's selection (or recent output, ANSI-stripped via `usePty.getRecentOutput`) to shared memory (`memoryWrite`) or into the other panes.
- **Agent activity** (`pty-manager` → `pty:state` event → store `paneAttention`): a per-pane idle timer flips agents between `working` and `waiting`; this drives the pane "waiting" badge and the conductor, and is purely about "finished a turn" — it does **not** notify. **Notifications are question-gated:** going `waiting` only fires the discrete "needs you" signal when the agent is actually blocked on an answer. `attachPty` keeps a rolling, ANSI-stripped `PtyEntry.recentOutput` tail and, on going quiet, runs `looksLikeQuestion()` (permission prompt / `y/n` / selection-menu patterns) against it. Only on a match does it (a) send `pty:attention` → renderer `addPaneNotification` (the TopBar bell, regardless of focus) and (b) fire an OS `Notification` (only if the window is unfocused). Both still require `PtyEntry.hadInput` (set in `ptyInput`) so a freshly-spawned agent at its prompt never pings. The idle threshold is the module-level `agentIdleMs` (default 4000), configurable in Settings → General (persisted as the `agentIdleMs` app setting; `appsettings.ts::applySideEffects` pushes changes live to `pty-manager.ts::setAgentIdleMs`, and `loadPersistedSettings()` applies it at startup). Cleared on focus/exit.
- **File management in the explorer** (`FileExplorer.tsx`, pure `src/lib/fileOps.ts` + `electron/lib/fsOps.ts`, IPC `fs:create/rename/move/copy/duplicate/trash/chmod/import/openPath`): the full IDE file-manager surface — multi-select (Ctrl/⌘-click, Shift-range, Ctrl+A), cut/copy/paste (Ctrl+X/C/V, cut rows dim until pasted), drag-and-drop move (hold Ctrl/Alt to copy), drag-in from Explorer/Finder (`fs:import`, paths via `webUtils.getPathForFile` since Electron 32 removed `File.path`), inline New File/New Folder rows, F2 rename, Ctrl+D duplicate, Delete → OS trash, copy absolute/relative path, open with the default app, reveal, and the POSIX permission grid / Windows read-only toggle. Keyboard navigation (arrows expand/collapse, Enter opens) runs off a focusable container; every handled key calls `stopPropagation` so a rebound *global* shortcut can't double-fire. **Every mutating handler is workspace-confined** by `assertInsideWorkspace` — `allowRoot` exists only for *container* arguments (where a new file or paste lands); the resulting child path is always re-checked without it, and `.swarmmind` stays off limits. Collisions never clobber: a move/copy onto an existing name gets a Finder-style free name (`nextAvailableName` → `x copy.ts`, `x copy 2.ts`), and a folder can never be moved or copied into itself or its own subtree. Moves report through `onFileRenamed` so open editor tabs (and the remembered-expanded set) follow the file instead of dangling at a dead path — a tab left on a moved path would recreate the old file on the next save. Pure path/naming/guard logic lives in the two `lib/` modules and is unit-tested; `node tests/fileops-verify.mjs` drives the whole thing against the built app and real disk state, including the containment guards.
- **Session history & scrollback** (`electron/ipc/sessions.ts`): `session:list` reads `~/.claude/projects/<encoded-cwd>/*.jsonl` for the Claude session picker (`SessionPicker.tsx`); `scrollback:load/save` persist per-pane terminal output under `{root}/.swarmmind/scrollback/<paneId>.log` (debounced from `usePty`).
- **Command palette** (`CommandPalette.tsx`, store `commandPaletteOpen`, Ctrl/⌘-K) and **terminal search** (`@xterm/addon-search` in `usePty`, Ctrl-F per pane).
- **Per-pane title/colour**: `PaneLeaf.title`/`color` (persisted), edited via title-bar double-click and the context-menu swatches.
- **Orchestration — Conductor + Lead** (`hooks/useConductor.ts`, `OrchestratorBar.tsx`, store fields prefixed `orchestrat*`/`leadPaneId`/`paneTask`): turns the existing task queue + the `pty:state` `waiting` signal into an autonomous control loop. `useConductor()` is mounted once in `App.tsx`; its tick is an **idempotent reconciler scheduled event-driven** — woken by swarm-bus events (pure `isWakeEvent` gate in `conductor.ts`: task/message/memory/pane changes; the conductor's own `dispatch`/`synthesis` output and telemetry types are excluded to avoid echo) and by store changes (pane attention/tree, orchestration controls), coalesced through a 150ms debounce, with a 5s heartbeat kept **only** for the time-based watchdogs (stall nudge, decompose timeout). It spends **zero** model tokens — code does the wiring, panes do the thinking. Three modes (`orchestrationMode`: `off`/`assisted`/`auto`, toggled in `OrchestratorBar`, shown as a TopBar dot). Each tick: (1) **completion sweep** — a worker reports done by calling `task_update(id,'done')` + `memory_write('result:<id>',…)` over MCP; the loop watches `taskList`, collects the result, and frees the pane (`paneTask` maps paneId→taskId); (2) **dispatch** — finds the next `pending` task whose `depends_on` (new comma-separated `tasks.depends_on` column + `task_create` MCP arg) are all `done`, matches it to a free worker pane by `assigned_agent`, and injects a single-line prompt via `ptyInput` (in `assisted` mode it raises an `orchestratorProposal` for `conductorControls.approve()`/`skip()` instead); (3) a designated **lead pane** (`leadPaneId`, optional) is prompted to **decompose** `orchestratorGoal` into tasks at run start and to **synthesize** results once all tasks finish (`orchestratorPhase`: `idle`→`running`→`done`). Worker/lead panes must already be running their CLIs — the conductor injects prompts, it does not spawn agents. **Spend guardrail:** an optional per-run budget (`orchestratorBudgetUsd`, the OrchestratorBar `Budget $` field, persisted per workspace as `orchestratorBudget:<id>`) stops `auto` mode dispatching **new** work once the swarm's reported spend — summed from the store's `paneCost`, which `pty-manager` fills from each agent's own cost output — reaches the ceiling. In-flight agents are left to finish (killing them would strand half-done work) and `assisted` mode is unaffected, since a human approves each dispatch there. Pure `totalSpend`/`budgetStatus`/`parseBudget` in `conductor.ts` (unit-tested); note `parseBudget` returns `null`, never `0`, for junk input — a `0` budget would read as "exceeded" and pause the run on a stray keystroke. **Robustness** (session-scoped refs, reset on each run): a `failed` task is auto-reset to `pending` and re-dispatched up to `MAX_RETRIES`; a dispatched worker that goes idle (`paneAttention === 'waiting'`) past `STALL_MS` while its task is still `in_progress` gets one nudge to report completion; if the lead produces no tasks within `DECOMPOSE_TIMEOUT_MS` it's re-prompted once, then the loop gives up rather than hanging. **Progress heartbeat + escalation brain**: workers are told (in `buildDispatchPrompt`) to post periodic `task_note` pings; `sweepAction` tracks the last note-change time (`lastProgressRef`) and, if a task shows **no progress for `STUCK_MS`** (default 180s) — whether its worker went silent `waiting` or is spinning `working` forever (the nudge's blind spot) — returns `escalate`. Escalation (and a retry-exhausted `give_up`, and `findUnassignable` **deadlock** tasks pinned to an absent agent) is routed to the **lead** via `buildEscalationPrompt` — the lead reasons and reassigns / re-splits / drops the task via MCP instead of the loop silently giving up; with no usable lead it's surfaced for attention. Guarded by `escalatedRef` (once per task — a re-failing task is surfaced, never loops the lead). Opt-in `orchestratorReportToLead` (OrchestratorBar checkbox) also streams each completion to the lead mid-run (`buildLeadReportPrompt`) so it can course-correct, not only at synthesis. `escalation` swarm events are telemetry (excluded from `CONDUCTOR_WAKE_EVENTS` to avoid echo). **Every per-tick decision is a pure function in `src/lib/conductor.ts`** (sweep/watchdog/dispatch/review/synthesis/message routing + the prompt builders, unit-tested in `tests/lib-units.mts`); the hook is only the impure shell — change orchestration behaviour there, not inline in the hook. The activity log is persisted per workspace (debounced app setting `orchestratorLog:<id>`, loaded on workspace switch).
- **Worktree Review** (`WorktreeReview.tsx`, store `reviewOpen`, TopBar branch icon): the payoff of per-pane worktree isolation. Lists each SwarmMind-managed worktree (under `.swarmmind/worktrees/`), shows its diff vs the main checkout's branch (`getBaseBranch`) — committed work **and** uncommitted changes, since `git diff <base>` runs from inside the worktree — with per-file +/− stats, a file picker, and a coloured unified-diff view. Actions: **Commit all** (stage + commit inside the worktree so the work becomes mergeable), **Merge into `<base>`** (merges committed work; aborts and reports on conflict so the main checkout stays clean), **Discard** (remove worktree + delete branch). Git ops live in `git-manager.ts` (`worktreeDiffStat`/`worktreeDiff`/`worktreeCommit`/`mergeBranch`) behind `git:*` IPC.
- **Center overlays** (store `boardOpen`/`graphOpen`/`reviewOpen`, mutually exclusive, toggled from TopBar): App.tsx picks `KanbanBoard` → `MemoryView` → `WorktreeReview` → `FilePanel` → `CenterArea` by precedence. `graphOpen` renders `MemoryView.tsx`, a tab host with **Graph | List** tabs: `MemoryGraph.tsx` (dependency-free SVG force-directed graph — nodes = agents/entries/tasks, links = wrote / assigned-to — with drag, pan, wheel-zoom, fed by `useMemory`) and `MemoryPanel.tsx` (editable list of entries + tasks with agent filter, inline edit/delete). Note: the left-sidebar toggle is confusingly named `kanbanOpen`/`toggleKanban` but controls `WorkspaceSidebar` (the workspace list), not the board.

- **Session export** (SwarmTimeline header **⬇ Export**, pure `src/lib/sessionExport.ts`, IPC `export:saveSession` in `electron/ipc/events.ts`): the event log rendered as a **self-contained HTML report** (stat tiles, agent legend, day-grouped timeline; inline CSS only, every payload string escaped) or a **Markdown digest**. The renderer builds both artifacts; the save dialog's chosen extension (.html/.md) picks which one main writes (then reveals it in the file manager). Agent identity colours reuse the app's fixed brand palette with a deterministic fallback wheel.

- **Multi-file Composer** (`ComposerPanel.tsx`, backend `swarmAgent:compose`, store `composerOpen`, TopBar wand icon / palette / SwarmAgent `open_view('composer')`): Cursor's "Composer" — describe a change in natural language and the AI proposes coordinated edits across several files at once. Context files (seeded from open editor tabs, add more via a fuzzy `fsListFiles` picker) are sent with the instruction; the model returns a **strict JSON plan** (`{summary, changes:[{path, action:'edit'|'create', content}]}` — full new file contents, parsed defensively in main) which the panel previews as per-file diffs (dependency-free LCS `lineDiff`), each with a checkbox. **Apply** optionally takes a **safety checkpoint first** (the "Snapshot first" toggle → `checkpointCreate(…, 'composer')`, so the whole multi-file change is reversible in one action from the Checkpoints panel; best-effort, reports `unavailable` on a non-git workspace), then writes the selected files via `fsWriteFile` (now `mkdir -p`'s parents so new files in new dirs work) and updates any open editor tabs in place. A center overlay like the others (added to `ALL_OVERLAYS_CLOSED`).
- **Editor view affordances — folding, word wrap, position memory** (`src/editor/folding.ts`, pure `src/lib/editorViewState.ts`, `FileEditor.tsx` status bar). Three separate things, verified together by `npm run editor-ux-verify`:
  - **Fold gutter.** `basicSetup`'s `foldGutter` is switched **off** (it takes no options, so its markers can't be styled) and replaced by `codeFolding` — `foldGutter({markerDOM})` drawing one SVG chevron that *rotates* between states, instead of CodeMirror's default text characters `⌄`/`›` whose size and baseline came from whatever the monospace font did with those codepoints. Open markers are hover-revealed and closed ones stay lit in the accent colour (VS Code's behaviour: a folded region is hidden state and must announce itself). Fold-all / unfold-all sit in the status bar; `@codemirror/language`'s `foldKeymap` already binds `Ctrl-Shift-[`/`]` and `Ctrl-Alt-[`/`]`. **Gotcha for tests:** the first `.cm-fold-marker` in the DOM is CodeMirror's zero-height width-reservation *spacer*, built from the closed state — filter by gutter-element height or you'll try to click a ghost.
  - **Word wrap** (Alt+Z, status-bar toggle, persisted as the `editorWordWrap` app setting, loaded in `App.tsx`). Applied through a `Compartment`, not by rebuilding the extension array: a rebuild would tear down and recreate the ghost-text and inline-edit plugins — dropping an in-flight completion — to toggle a boolean.
  - **Per-file cursor + scroll memory.** `FilePanel` renders `<FileEditor key={activePath}>`, so every tab switch unmounts the editor; without this you return to line 1 of a 2000-line file. The position is tracked **live** into a ref (rAF-coalesced `scroll` listener + the update handler) and written to a bounded MRU map on unmount. **Reading `scrollTop` in the unmount cleanup does not work** — effect cleanups for a deleted subtree can run after React has detached the node, and a detached element reports `scrollTop === 0`, so it faithfully remembered "top of file" every time. Selection survived (it lives in CodeMirror state, not the DOM), which made the bug look half-working. Restoring the scroll also needs a bounded rAF retry: at `onCreateEditor` only the first viewport of lines is rendered, so `scrollHeight - clientHeight` is still ~0 and any target beyond it clamps to 0. `editorViewState.ts` (MRU eviction + the clamp that keeps a stale offset from throwing into the error boundary) is pure and unit-tested.
- **Snippets** (`src/lib/snippets.ts`, store `snippets`, `FileEditor.tsx` status-bar **❏ Snippets**): reusable code fragments saved from a selection and inserted at the cursor — not AI, so fully testable offline. The dropdown lists saved snippets (click to insert, × to delete) and offers "Save selection…" (enabled when text is selected) with an inline name field. Persisted globally as the `editorSnippets` JSON app-setting (loaded in `App.tsx`); pure CRUD/filter/parse logic in `src/lib/snippets.ts` is unit-tested. Note: distinct from `SkillsLibrary` (drag-drop *prompts* for agent panes) — snippets are editor text.
- **Rename symbol across files — F2** (`FileEditor.tsx`, store `composerSeed`/`openComposerWith`): press **F2** on an identifier → a small popover prefilled with the current name; entering a new name greps the workspace for usages (`fsSearchFiles`), then routes a precise rename instruction + the matched files (plus the current file, capped at 12) through the **Composer** via `openComposerWith({instruction, contextPaths})`. The Composer consumes the one-shot `composerSeed` on open (prefills the instruction, loads the context files) and clears it — so rename reuses the Composer's preview/checkpoint/apply pipeline rather than adding new infra. Identifier-guarded (won't fire on non-words); the instruction tells the model not to touch substring matches, strings or comments.
- **AI diagnostics / "Fix with AI"** (`FileEditor.tsx`, backend `swarmAgent:diagnose`, `@codemirror/lint`): the status-bar **⚠ Diagnose** button sends the open file (line-numbered) to the model, which returns strict-JSON problems `[{line, severity, message, fix}]`. These are mapped to CodeMirror `Diagnostic`s and rendered in `lintGutter()` (underlines + gutter markers); each carries a **"Fix with AI"** action that opens the Cmd-K inline-edit widget on the flagged line prefilled with the suggested fix — i.e. diagnostics feed straight back into the inline-edit flow. The button shows analyzing / "✓ No issues" / "⚠ N issues"; diagnostics are cleared on file switch.
- **Ghost-text autocomplete — Tab** (`src/editor/autocomplete.ts`, backend `swarmAgent:complete`, store `ghostTextEnabled`): Copilot/Cursor-style inline AI completions. A `ViewPlugin` debounces (350ms) on typing, sends prefix/suffix around the cursor to a fast non-streaming completion (via `runChat`, `fast` mode — see the provider abstraction), and shows the prediction as dimmed ghost-text via a widget decoration + `setGhost` `StateField`; **Tab** accepts (high-precedence keymap, falls through when no ghost), **Escape** or any edit dismisses. Stale responses are dropped by a request counter. **Off by default** (it spends tokens on every typing pause) — toggled from the editor status-bar **⊳ Autocomplete** button, persisted as the `editorGhostText` app setting (loaded in `App.tsx`). The plugin reads language + enabled state via refs so it's never rebuilt.
- **Inline AI edit — Cmd/Ctrl+K** (`FileEditor.tsx` + `src/editor/inlineEdit.ts`, backend `swarmAgent:editCode`): the Cursor-style "vibe coding" surface inside the CodeMirror editor. Select code (or place the cursor for a pure insertion) and press **Ctrl/⌘-K** (or the status-bar **✦ Edit with AI** button) → a floating prompt appears at the selection. Typing an instruction calls a focused, single-turn completion (via `runChat`, so it uses whichever provider is configured, but with `EDIT_SYSTEM_PROMPT` that returns raw code only — a defensive fence-strip handles models that wrap output) seeded with the selection plus ±`CONTEXT_LINES` of surrounding context. The prompt supports **@-mention file context**: typing `@` opens a fuzzy file-path autocomplete (from `fsListFiles`, warmed once per editor mount) — picked files are read (`fsReadFile`, capped/sliced) and sent to the model as "Referenced files" so it can match a style or reuse a helper. The result streams into the widget, then replaces the selection and enters an **accept (⏎) / reject (Esc) / regenerate** preview, with the changed range tinted via a CodeMirror decoration `StateField` (`setEditHighlight`). Reject restores the original text; a cancel-while-streaming guard (`activeReqRef`) drops a late result so it's never applied. **Keybinding note:** Ctrl/⌘-K is also the global Command Palette shortcut; the editor's keymap (`Prec.highest`) handles it first, and `App.tsx`'s global handler skips `command-palette` when the event target is inside `.cm-editor`, so the same key means "inline edit" in the editor and "palette" everywhere else (mirroring Cursor).
- **Next-edit prediction — "Tab to jump"** (`FileEditor.tsx` + pure `src/lib/nextEdit.ts`, backend `swarmAgent:nextEdit`): Cursor's tab-to-jump. After an inline AI edit is **accepted**, `acceptInlineEdit` fires a best-effort `swarmAgentNextEdit` call (the just-edited line range + full numbered source) to a non-streaming completion (`NEXT_EDIT_SYSTEM_PROMPT`, strict JSON `{line,instruction}` or `{none:true}`). The renderer hands the raw prediction to `resolveNextEditTarget(pred, doc.lines, justEditedLine)` — the pure, unit-tested validator that clamps the line into the document and rejects jumping back onto the line just edited — and on a valid target shows a floating **Tab** chip (bottom-right of the editor) describing the follow-up. Pressing **Tab** (or clicking the chip) calls `jumpToNextEdit`: it selects the target line and reopens the inline-edit widget prefilled with the suggested instruction, so accepts chain into the next edit. The Tab/Escape handlers live in the same `Prec.highest` keymap as F2 and **fall through** (return false) when there's no hint, so ghost-accept and default Tab still work; the once-built keymap reads live state via `jumpRef`/`editRef`/`hintRef`. The hint is cleared on file switch and on any manual doc edit.
- **One-click apply from chat** (`SwarmAgentChat.tsx` `ApplyFromChat` + pure `src/lib/codeBlocks.ts`): a completed SwarmAgent reply that contains **file-targeted** fenced code blocks (path on the fence info string — ```` ```ts src/foo.ts ````, ```` ```ts:src/foo.ts ````, `title=`/`file=` — or on the line just before the fence — `` `src/foo.ts` ``, `**src/foo.ts**`, `File: …`) shows a **Review & apply** button. `extractFileBlocks` (pure, unit-tested) pulls `{path,language,content}` out of the markdown; the button calls `openComposerWith({ instruction, contextPaths:[], plan:{summary,changes} })` with a **pre-built plan** so the Composer skips the model round-trip and renders the diff/checkpoint/apply UI directly against the exact blocks. The Composer's seed effect branches on `seed.plan`: it seeds `changes`/`summary`/`selected`, resolves each file's current content for diffing (`''` for create/unreadable), and jumps to `phase:'result'`. Only rendered in the main window's chat (not the workspace-less widget).
- **Composer auto-context — "Suggest relevant"** (`ComposerPanel.tsx` + pure `src/lib/retrieval.ts`): the first, model-free step toward automatic right-context selection (Cursor's strength). Instead of hand-picking context files, the **✦ Suggest relevant** button tokenizes the instruction (camelCase/snake_case-split, noise-dropped via `tokenize`), greps the workspace for its salient terms (`fsSearchFiles`, bounded), groups the matches by file, then **BM25-ranks** those files by their matched-line snippets (`rankDocs`) and adds the top few to the context chips. Bounded by construction — only files that grep-match a query term are ever read. Pure ranker (`retrieval.ts`) is unit-tested. Ranking is **hybrid**: BM25 always, fused (reciprocal-rank fusion, `fuseRankings`) with on-device **embedding** similarity (`rankByEmbedding`/`cosineSim`) once the local model is warm — see below.
- **SwarmVoice — dictation** (`hooks/useVoice.ts`, `SwarmVoice.tsx`, `VoiceWidget.tsx`, pure `src/lib/vad.ts` + `src/lib/dragWidget.ts`): local Whisper (transformers.js, `.en` models, disk-cached via `voiceCache*` IPC) transcribing straight into the active pane's PTY. Three things are load-bearing:
  - **The waveform never re-renders React.** `useVoice`'s analyser writes into a module-scope level buffer; `WaveformBars` (one shared component — the TopBar button, the voice widget, SwarmAgent's chat and its desktop widget all use it) runs its own rAF and mutates the bars' `transform` directly. Recording used to push React state ~60×/s purely to animate five bars. Read levels with `readAudioLevels()`; do **not** reintroduce a `levels` prop.
  - **Decode is one pass.** `decodeTo16kMono` decodes the recorded WebM/Opus on a 16 kHz `OfflineAudioContext`, so `decodeAudioData` resamples to Whisper's rate *as part of the decode*. The old path opened a device-rate `AudioContext` (a real output device, just to discard it), then rendered the whole clip through a second `OfflineAudioContext` only to resample — overhead that scaled with clip length and showed up as a pause between "stopped" and "transcribing". The two-pass route survives as a guarded fallback.
  - **Auto-stop is a pure state machine** (`vad.ts`, unit-tested): the recording ends itself after a pause instead of needing a second keypress. All three guards matter and are tested — never stop before speech is heard, never stop a clip shorter than `minDurationMs`, and only stop once silence has actually lasted `hangoverMs`. Toggle in Settings → General (`voiceAutoStop`).

  **The floating widget** (`VoiceWidget.tsx`, store `voiceWidgetOpen`/`voiceWidgetPos`, toggled by the icon-only TopBar voice button — that button now shows/hides the pill rather than recording; the keyboard shortcut still starts/stops dictation directly) is a ~73×30 pill holding only the circular SwarmMind orb and the live audio line (the orb drawn concentric with the pill's left cap — `CAP_RADIUS`/`ORB_INSET` — so the round mark nests into the round end instead of floating in a straight-edged gap; while the model loads or a clip transcribes it wears the same rotating conic ring as the SwarmAgent orbs, `.voice-orb.is-busy` in `global.css`, since the bars are still in those states) — dictation happens while you're watching a *terminal*, not the top bar, and that only works if the control is small enough to park anywhere without covering your work. State reads from colour and motion (dim/still idle, accent-lit with a moving waveform when listening, a slow logo pulse while loading or transcribing); everything a bigger panel would spell out — status, target pane, last transcript — is in the `title` tooltip, so nothing is lost, it's just not always on screen. It's presentational: `SwarmVoice` owns the single recorder and passes state down, so the two surfaces can't disagree. The pill is too small for a separate grip or close button, so **the whole thing is button *and* handle**: a press under `DRAG_THRESHOLD` px toggles dictation, more than that drags, and right-click closes. Placement maths is pure (`dragWidget.ts`): it clamps on drag, on window resize, and on restore, so a position saved on a larger display can't strand the widget off-edge. `npm run voice-verify` drives the real widget (open → drag → persist → reload → off-screen rescue → short-press-is-not-a-drag → close).
  **Known limit:** Whisper inference runs on the renderer's main thread, so a long clip briefly janks the UI. Moving it to a worker is blocked on the model cache going through `window.swarmmind` IPC, which workers can't reach.

- **Wake word — hands-free dictation** (`hooks/useWakeWord.ts`, pure `src/lib/wakeWord.ts`, `WAKE_VAD` in `vad.ts`, Settings → General, store `voiceWakeEnabled`/`voiceWakePhrase`). Armed, the user says "hey swarm" instead of clicking the pill. Two shapes: the phrase alone opens dictation; **"hey swarm, run the tests" sends the command in one breath** (the matcher returns the remainder, sliced out of the *original* transcript so casing and punctuation survive into the terminal). Verified by `npm run wakeword-verify`.
  - **There is no wake-word engine, by design.** Whisper is already on-device, so arming means running short `WAKE_VAD`-delimited segments through the model that's already loaded and asking `matchWakeWord` about the result. No new dependency, still fully offline. A Whisper pass costs one *utterance*, not one second — the VAD gates it, so a silent room costs an analyser rAF and nothing else. It's opt-in because speech near the mic does get transcribed locally to be checked (never transmitted — but real CPU).
  - **`WAKE_VAD` is the same detector with a much shorter fuse** (700ms hangover vs dictation's 1800ms). At dictation's timing the phrase wouldn't reach the model for nearly two seconds, which reads as a broken assistant; the ceiling still has to hold phrase-plus-command in one breath.
  - **Matching has to absorb how a speech model behaves**, which is why it's pure and unit-tested: punctuation/case are invented by the model ("Hey, Swarm."), long words get an edit-distance budget (swarm/swarn) but **short words get none** — one edit from "hey" is also her/hen/hex/they, and a false fire types into the user's terminal while a miss just costs a repeat. Matching is anchored to the first couple of words so a mid-sentence "…tell the swarm about it" can't trigger it. `isValidWakePhrase` rejects phrases too short to be distinct (enforced in the store *and* surfaced in Settings — silently reverting would leave the user saying a phrase that can never fire).
  - **It's a separate hook, not a mode inside `useVoice`.** The dictation path there is tuned and load-bearing; threading a second lifecycle through its `start`/`stop` machine would risk every dictation for an opt-in feature. The listener owns its own mic/recorder and shares only the genuinely subtle parts — `ensureVoiceModel` (same singleton, never a second load) and `transcribeAudio` (the one-pass decode + the `{language, task}` trap).
  - **Mic contention is the sharp edge.** The listener is suspended (`paused`) whenever the recorder is doing anything, and on a phrase-only wake it stops its own tracks *before* invoking the callback rather than waiting for React to run the effect cleanup — otherwise dictation's `getUserMedia` races the still-open stream, and the listener can hear the user's own dictation and re-trigger off it. Re-arming rides on `paused` going true→false, with a cycle-counter fallback for when the hand-off never happened (no active pane). `wakeword-verify` counts live `MediaStreamTrack`s to assert the peak never reaches two and that **disabling really releases the mic** — the worst possible bug here, and invisible from the code since the tracks live in an effect closure.

- **On-device embeddings** (`src/lib/embed.ts`, pure math in `src/lib/retrieval.ts`): a key-free semantic layer for retrieval, mirroring SwarmVoice's transformers.js setup (`allowLocalModels=false`, the same `voiceCache*` IPC disk cache, locally served ONNX WASM from `public/ort/`). `embedTexts()` lazily loads `Xenova/all-MiniLM-L6-v2` (384-dim, ~23 MB quantized, mean-pooled + normalized) and embeds bounded text; `preloadEmbedder()`/`embeddingsReady()` let the UI warm it in the background so a click never blocks on the download. `embed.ts` is the **impure runtime**; the vector math it feeds (`cosineSim`/`rankByEmbedding`/`fuseRankings`) stays pure in `retrieval.ts` and is unit-tested. Composer auto-context uses it best-effort: when the model is ready it fuses BM25 + embedding rankings (RRF); otherwise it warms the model and uses lexical-only that round (offline-safe). Not imported by the test runner (only the pure `retrieval.ts` is).
- **Whole-repo semantic index** (`src/lib/codeIndex.ts`, pure deps `src/lib/chunk.ts` + `src/lib/retrieval.ts`): the step beyond grep-bounded auto-context — instead of only ranking files that lexically match a query term, it ranks the **whole repo by meaning**. `buildIndex(rootPath)` lists indexable files (bounded by `MAX_FILES`/`MAX_CHUNKS`/`MAX_FILE_BYTES`), splits each into overlapping line windows (`chunkText`), embeds them in batches (`embedTexts`, on-device), and persists the vectors to `{root}/.swarmmind/vector-index.json` (`loadIndex` rejects a stale `version`/`model`). `queryIndex(entries, query, k)` embeds the query, scores every chunk (`rankByEmbedding`), then collapses to one row per file keeping its best chunk (`dedupeByPath`). Composer's **✦ Suggest relevant** uses it when an index exists (the panel's **Build index** button creates one, reporting embed progress), fusing those repo-wide hits with the grep/BM25 round; like `embed.ts` it's the **impure runtime** (fs + embeddings) and the math it leans on (`chunk.ts`, `retrieval.ts::rankByEmbedding`/`dedupeByPath`) is the unit-tested part.
- **Verify → fix loop** (`ComposerPanel.tsx` + pure `src/lib/verify.ts` + constrained `electron/ipc/verify.ts`): the safe, human-in-the-loop core of "agent-mode iteration". After a Composer plan is **applied**, the panel offers to run one of the workspace's **own npm scripts** (picker defaults to typecheck/test/lint/build via `pickVerifyScript`/`orderVerifyScripts`); on a non-zero exit, **✦ Fix errors with AI** condenses the output (`summarizeFailure` — error-like lines first) into a follow-up instruction (`buildFixInstruction`) and re-runs the Composer plan pipeline so the model fixes its own change. **Constrained runner safety:** `verify:run` executes **only** a script that exists in the repo's `package.json scripts` (allowlist) **and** matches a strict charset (`isSafeScriptName` — no shell metacharacters), via `execFile` with no shell on POSIX (`npm`) and `shell:true` only on Windows where `npm.cmd` requires it — so even a malicious cloned repo's `package.json` can't turn this into arbitrary command execution. Hard timeout + bounded output. Pure control logic (`verify.ts`) is unit-tested; the main-process copy of `isSafeScriptName` is duplicated (main can't import renderer paths) and must stay in sync. Every step is an explicit click — no autonomous process execution.

### TypeScript language service (real LSP)

`electron/lsp/*` runs a **`ts.LanguageService` in a `worker_threads` worker** — the last thing Cursor had that SwarmMind didn't. There is no external language server to install or spawn: the `typescript` package (a **runtime** dependency, not a dev one — `externalizeDepsPlugin` only externalizes prod deps) *is* the engine. It covers TS/JS/TSX/JSX.

- **Why a worker:** `ts.LanguageService` is synchronous and the first program build takes ~1.2s. The main process pumps every PTY, so doing this on it would freeze all terminals. `electron/lsp/worker.ts` is a **second main-process entry** in `electron.vite.config.ts` (emitted as `out/main/lsp-worker.js`); `client.ts` resolves it as `__dirname/lsp-worker.js`, so those output names are load-bearing. The client degrades to "no result" on crash/timeout and respawns — never throws into the editor.
- **Self-contained requests:** every query (`lsp:diagnostics/hover/definition`) ships the editor's live buffer, so the service always answers against unsaved text and a worker restart costs only the in-flight call (no resync handshake).
- **Program roots = the open files + the project's ambient `.d.ts` files.** TS pulls in the import closure itself, so we never enumerate the repo. **The `.d.ts` part is not optional:** ambient declarations are included by being *listed* in the project, not by being imported — drop them and `window.swarmmind` becomes "Property 'swarmmind' does not exist on Window" and `import x from './y.png'` becomes "Cannot find module" on every file.
- **Which tsconfig owns a file** is resolved through **project references** (pure, unit-tested `chooseProject` in `electron/lib/tsLsp.ts`). Taking the *nearest* tsconfig is wrong in this very repo: the root `tsconfig.json` is solution-style (`{"files": [], "references": […]}`), declares no files and no `jsx`, so trusting it flags every `.tsx` as broken. Roots are stored in their **real case** — TS echoes root names back in definition results, and normalized (lowercased) names would break navigation on a case-sensitive filesystem.
- **The payoff — compiler errors feed the AI fix loop.** `src/lib/diagnostics.ts::mergeDiagnostics` (pure, unit-tested) merges the language service's diagnostics with the model's (`swarmAgent:diagnose`) into one lint list: the compiler is authoritative (a TS *error* on a line suppresses an AI diagnostic there — that's the model restating the type error), while AI findings elsewhere survive. Because they land in the same list, **every real type error inherits the existing "Fix with AI" action** → a prefilled Cmd-K inline edit. Diagnostics run automatically (debounced 500ms, no tokens); hover and Ctrl/⌘+Click / F12 go-to-definition live in `src/editor/lsp.ts`.
- **References & compiler-exact rename.** Shift+F12 opens an in-editor drawer of `findReferences` results (def/write badges, click navigates; peek-style — a cross-file jump remounts the keyed editor and dismisses it). F2 on a TS/JS file asks the worker for `findRenameLocations` with `providePrefixAndSuffixTextForRename: false` (alias-renames like `import { double as twice }` would betray "rename across files"; safe because nothing applies silently) — the worker applies spans against **its own snapshots** (`applyTextEdits` in `tsLsp.ts`, pure/unit-tested; refuses overlaps) and returns full new file contents, which `src/lib/rename.ts::buildRenamePlan` (pure, unit-tested; rejects out-of-root files) turns into a pre-built Composer plan → the existing diff/checkpoint/apply pipeline. Non-TS files keep the model-mediated grep flow as fallback.
- **`lspClose` fires on tab close only (`FilePanel.closeTab`), never on file switch.** Every open tab must stay a program root: evicting the previous file on switch silently blinds cross-file queries (references/rename) to the files that import the one on screen — diagnostics/hover/definition don't notice because they only need the *current* file's import closure. This regression is exactly what `lsp-verify`'s references stage exists to catch.
- **`linter(null)` in `FileEditor`'s extensions is load-bearing.** It installs `@codemirror/lint`'s state field (and the lint tooltip) up front. Without it, `setDiagnostics` takes its fallback path and appends the lint extensions via `appendConfig` *in the same transaction* that carries the diagnostics — but a field added by `appendConfig` starts from `create()` and never sees that transaction's effects, so the first batch is silently dropped. `lintGutter()` has its own field, so the symptom is a gutter marker and a problem count **with no underline and no tooltip**.
- **Verify it for real:** `npm run lsp-verify` (Playwright on the built app) drives a genuine type error to a rendered squiggle, asserts the tooltip carries the compiler's message *and* the Fix-with-AI action, F12-navigates across files, Shift+F12-lists references across files, and lands an F2 rename as a two-file Composer plan.

### SwarmAgent desktop widget (second window)

A small frameless, transparent, always-on-top floating window that hosts just the SwarmAgent chat, so the assistant stays reachable when the main window is minimized or hidden to the tray. It is the **same renderer bundle**, loaded with a `#widget` hash — `src/main.tsx` branches on `window.location.hash === '#widget'` and mounts `SwarmAgentWidget` instead of `App` (so none of App's heavy effects — PTYs, conductor, loops — run in the widget) and adds a `widget` class to `<html>` so the page is transparent and the card's rounded corners show. No extra Vite/electron-builder entry is needed.

- **Slim bar + dynamic height**: it starts as a small floating **bar** (just the input bar — `createWidgetWindow()` opens at 420×70 near the bottom-right) and grows **upward** to ~460px to show a compact transcript once a conversation is on screen. The renderer drives this: it sends the target height on `widget:resize`, and main re-bounds the window anchored to its bottom edge (so it expands above the bar, never below).
- **Window/lifecycle** (`electron/main.ts`): `createWidgetWindow()` (frameless, `transparent`, `resizable: false`, `alwaysOnTop: 'floating'`, `skipTaskbar`). It auto-shows when the main window fires `minimize`/`hide` and auto-hides on `restore`/`show`/`focus` (unless the user dismissed it this session — `widgetDismissed`). Tray menu gains **Show Chat Widget**. Dragging is pure CSS: the bar/header have `-webkit-app-region: drag` (buttons/inputs are `no-drag`), so the OS window moves around the desktop. The widget window also gets its own mic `setPermissionRequestHandler` for voice.
- **Appearance + voice**: `useAppearanceSync()` replays the persisted theme/accent/density/font settings into the widget's own document (it's a separate renderer), so the widget matches whatever the user picked. Voice input works via the same `useVoice` hook as the in-app chat (its own Whisper instance in this window).
- **Streaming** (`electron/ipc/swarmagent.ts`): `swarmAgent:chat` streams deltas to **`e.sender`** (the invoking window), so the widget — not just the main window — receives them.
- **Tool forwarding**: the widget runs its own `useSwarmAgent` loop but has **no workspace state of its own**, so it forwards each tool call. `useSwarmAgent({ runTool })` takes an injectable runner; the widget passes one that calls `window.swarmmind.widgetForwardTool(name,args)` → main process `widget:forwardTool` relays it as a `widget:runTool` request to the **main window**, which runs the real `runTool` (via `useWidgetBridge`, mounted in `App`) against its store/PTYs and replies on `widget:toolResult` (correlated by id, 60s timeout). So "open the board" / "what changed?" from the widget actually drive the main app. Both windows share the same `localStorage['swarmagent:history']` (same `file://` origin), giving conversation continuity across surfaces.

### Startup performance — lazy overlays

`App.tsx` eagerly imports only the always-visible shell (TopBar, CenterArea/terminal grid, StartScreen, sidebars). The on-demand center overlays — **FilePanel (CodeMirror, ~975 KB), KanbanBoard, MemoryView, WorktreeReview, ComposerPanel, SwarmTimeline, ChangesPanel, CheckpointPanel, BenchmarksPanel, SwarmAgentChat, LoopsPanel** — are `React.lazy(() => import(...).then(m => ({ default: m.X })))` (named exports → default-wrapped) and rendered inside a single `<Suspense fallback={…}>` around the center conditional. This keeps them (and CodeMirror) out of the initial chunk: the renderer entry bundle is ~1.33 MB instead of ~2.54 MB, so first paint (which only needs the terminal grid) is faster. When adding a new center overlay, prefer lazy-loading it the same way unless it's part of the default view. (Whisper/`transformers` voice was already a separate lazy chunk.)

### Icons

`src/components/Icons.tsx` is the shared set — one geometry family (24×24 box, `currentColor` stroke, no fill, round caps/joins), matching the file/folder icons `FileExplorer` already drew in. **Don't spell arrows with text glyphs** (`▾ ▸ ▲ ▼ ‹ › ↑ ↓`): those are font characters whose weight, size and baseline are decided by the UI font, so they sit off-centre beside a real icon, don't scale with their control, and can't animate. Two glyphs from different Unicode blocks don't even match each other. Colour comes from `currentColor`, so an icon inherits its button's hover/active/disabled states.

- `ChevronDisclosure` is the expand/collapse control for every tree: **one chevron that rotates**, not two glyphs that swap — expansion then reads as a single motion. Its `invisible` prop keeps leaf rows aligned with their siblings without drawing anything.
- Chevrons mean "there is more this way"; **arrows** (`ArrowUp`/`ArrowDown`) mean "move/order". Keeping them apart is what stops a sort indicator from reading as a collapse control.
- **Icons are drawn at 11–14px here, and that constrains the geometry.** `FoldVertical`/`UnfoldVertical` carry a centre line specifically because the obvious two-bare-chevrons drawing antialiased into an X and a diamond at 13px. Check a new icon at its real size (upscale a screenshot with nearest-neighbour) before assuming it reads.
